# Response to the graph audit of 22 September 2026

The audit read `ground/`, replayed `runs/2026-09-22/decisions.jsonl` (3,307 decisions, graph v4 to v15)
and found fourteen issues. Its central claim was that the worst problems sat in the code around jev
rather than in jev's answers, and that is what the numbers say. This is what changed, what it measured,
and what it did not settle.

Before changing anything, the audit's numbers were re-measured from the same log. They hold:

| Claim | Audit | Re-measured here |
|---|---|---|
| Direction decisions with the top two within 0.15 | 427 of 3,307 | 427 |
| Distinct 128-unit cells over the whole run | 56 | 56 |
| `standing_order` / `way.focus` / `way.not_for` lengths in the live v15 | 600 / 700 / 700, all cut mid-word | 600 / 700 / 700 |
| `way_margin` in every saved graph | 0.5 | 0.5 |
| Median input tokens per call | 3,190 | 3,190 |
| Median latency | 466 ms (p90 530) | 466 ms (p90 530) |
| `weapon` answered Keep | 3,307 of 3,307 | 3,307 |
| `fire` said yes | 6 | 6 |
| 8-tick windows with 300+ degrees and under 64 units | 659 | 736 |
| Walk decisions in the unsure band | 677 | 716 |

The last two differ by definition, not by fact: the audit skipped windows that cross an episode boundary
and used an open 0.35–0.65 band, and the first pass here did neither. Both definitions are now frozen in
[`ground/metrics.py`](../ground/metrics.py) — episode boundaries skipped, band open — and the report, the
run report and the replay tool all import them, so every later comparison is against the same ruler.

Two structural points the audit made underneath those:

- **Four of eight heads were lookup rules.** Three heads are left, and all three are judgments with no
  exact rule: how promising a direction is, how dangerous the scene is, what the priority is.
- **The mode was implicit in the criteria.** It is now an explicit machine in code — EXPLORE, APPROACH,
  OPERATE, FIGHT, RECOVER, DONE — with every transition an exact rule, and a reflex layer under all of
  them that never fires at zero ammo, never walks into a known wall and never re-commands a turn in flight.

## The design rules, and where each one lives

| Rule | Where it is enforced |
|---|---|
| Every fact a criterion mentions exists in the state | `decision_graph.lint`, called from `graph_config.validate`; it checks the question text **as rendered**, after `{dir}` substitution, so an unsubstituted placeholder is caught too |
| Anything historical is computed by code and written present-tense | `NavMemory`; jev never receives it as history |
| Any rule code can compute exactly stays in code | the three remaining heads; `tools/replay.py` keeps a code-only baseline honest |
| Every threshold has an unsure band and a named fallback | `pick_sector` + `frontier_fallback` |
| Questions are isolated, so each head gets only its blocks | `HEAD_STATE` and `state_for`; `lint` rejects a criterion naming a block its head is not given |
| Invariants in code at runtime | `reflex` |
| Pin the model, gate changes on replay | `cfg["model"]`, `tools/replay.py`, `tools/boundary_set.py` |

## What the replay measured

`tools/replay.py` runs logged states through the new graph without the game: a code-only pilot that
encodes the rubric as an exact function, and jev itself, repeated so that answers that flip between
identical passes show up.

### The unsure band had to be calibrated, and the first version of it was wrong

The band was first written as "a near tie **and** low confidence". Replaying 120 states showed it never
fired once: jev reported 0.94–0.99 confidence on every sector while the top two sat **0.01 to 0.08 levels
apart**. That is not a contradiction. Each sector is scored by its own isolated question, so `confidence`
says how concentrated that sector's answer is on its own rubric — it says nothing about how far that
sector beats the others. For a composite score built from per-item Scores, the quantity to gate on is the
**gap between items**, and the band is now an `or`: either the ranking is too close to call, or the
answer itself is unconcentrated.

The first pass at this bucketed 120 states by that gap and read a clean cutoff out of it: 30% of rankings
flipped below 0.10 levels, and 0 of 51 flipped above. Repeating it on 150 states did not reproduce that —
the 0.05–0.10 bucket went from 5 flips in 17 states to 7 in 12 between two runs over the same log. The
per-bucket rates are too noisy at this sample size to name a threshold from. So `tools/replay.py` now
sweeps the threshold instead, re-cutting the saved cases without paying for the calls again:

| `select.unsure_gap` | States jev still decides (of 141) | Its commands that differ between three identical passes |
|---|---|---|
| 0.00 (no band) | 141 | 30 |
| 0.05 | 74 | 14 |
| 0.10 | 62 | 5 |
| **0.20** | **51** | **2** |
| 0.40 | 40 | 1 |
| 0.80 | 28 | 0 |

That is a cost/benefit curve, not a cutoff. **0.20 is the knee** and is what ships: jev still decides a
third of the states, and 93% of the irreproducibility is gone. Buying the last two unstable commands would
cost another 23 states of jev's authority, which is a bad trade for a model that is meant to be the pilot.
The number should be re-swept against the labelled boundary set before it moves again, and the comment in
`graph_config.py` says so.

### The honest check the audit asked for

The audit's own caveat was that every rubric level is close to an exact function of `space`, `ground`,
`door` and `exit_here`, and that if a ten-line code function matches jev on replayed states then jev is
not earning its latency yet. That check is `tools/replay.py --pilots code,jev`, and it is a gate, not a
footnote. Results are in `runs/2026-09-22/replay_v1.json`.

Over 141 replayed states, jev and the code-only function took the same direction on **90%** of them. Most
of that is not a comparison: on 80 of the 141 the band fired and both pilots took the same deterministic
fallback, so they agreed by construction. **On the 61 states where jev actually decided, they agreed on
79%** — jev differs from the rule about one time in five, and nothing here says which of the two is right.
The labelled boundary set is what would say, and it is not labelled yet.

The sharpest single example is one real call, kept in `runs/2026-09-22/worked_decision.json`
(`req_01a0ca69a9257928badc1736482115ce`, 422 ms): five of the eight sectors were all "never explored", and
jev scored them **2.97, 2.98, 2.98, 2.98, 2.99** at 0.97–0.99 confidence. That is the rubric answered
correctly — those directions really are equally promising *by the rubric* — and it is also a ranking with
no information in it. The tie-break belongs to code, and now goes there.

The reading to take from this: jev reproduces the rubric faithfully, and a rubric written as a function of
four enum fields is a lookup table however it is asked. jev will start earning its place here when the
state carries evidence no exact rule can read — the surface classifier's labels, a description of the
frame, the shape of the space rather than a four-way band of it. That is the next pass, and it is the
right reason to do it.

## The live run, and the result it produced

The flight side was rebuilt with the eight new channels, the XTCE regenerated, and the new graph flown for
150 seconds on E1M1. Everything in the stack works: all eight `DOOR_*` channels decode through F´ and
Yamcs, `NEW_*` carries novelty alone, all five modes were exercised (EXPLORE 142, RECOVER 26, APPROACH 7,
FIGHT 6, OPERATE 4), 31 ticks were decided by code alone, and the after-action review came back valid —
**on its second attempt**, because its first reply broke the margin bound, code rejected it with the
reason, and its own rationale then opens "Fixed the hard constraint: sector_margin(0.55) +
commit_bonus(0.35) = 0.9, under the 1.0 cap." That is the loop the old graph never had.

The walk, compared with the first 150 seconds of the 22 September run so the comparison is like for like:

| | Old graph, first 150 s | New graph, 150 s |
|---|---|---|
| Decisions | 193 | 185 |
| Median input tokens | 2,654 | **2,063** |
| Spin windows per decision | **0.07** | 0.32 |
| Distinct 128-unit cells | **29** | 25 |
| Path walked | **8,360 units** | 6,613 units |

**The new graph walked worse.** One run each, so the difference is not established — the audit's own point
that a single 3-minute run is one sample cuts both ways — but it is what was measured and it is not what
was hoped for.

The cause is measurable, and it is not the model. On the five consecutive decision pairs where the state
sent to jev was byte-identical, its scores moved by a median of **0.01 rubric levels** and never by a whole
level: jev is stable. The state is not. Between consecutive half-second decisions:

- **3.4 of 8 sectors change their `space` word** and **3.0 change their `ground` word**;
- the median sector holds the same `ground` word for **one tick** (p90: six).

So the pilot is being asked to commit to a direction on evidence that is re-rolled almost every tick. The
hysteresis is on the committed bearing, which is why it travels at all, but the scores it weighs that
commitment against are computed fresh from a genuinely different state each time. No amount of smoothing
on the *answers* can fix an input that jitters like that; the smoothing has to go where the jitter is.

That points back at the first item in the original handoff's honest list — "sensing errors dressed up as
navigation" — with a number attached this time. The next pass is to stabilise the sector words in the
payload or in `NavMemory` (hold a sector's word until the underlying reading has moved by more than its
band's width, rather than re-banding a noisy number every tick), and only then re-run this comparison.

## What this has not settled
- **The boundary set is unlabelled.** `tools/boundary_set.py` pulls 102 cases out of the run — 34 near
  ties, 34 with a door close, 34 stuck or blocked — and leaves a `label` field for a person to fill in.
  Until it is filled in, the replay compares pilots against each other, not against a right answer.
- **Ten live attempts per candidate** (verification plan, step 4) have not been run.
- **Token cost is down but not to the audit's estimate.** 3,190 → 2,261 median input tokens (29% less).
  The audit guessed "under 1,500" for the Score design; the rubric names its state paths in full, which
  costs about 420 characters per sector question and is the reason. Naming them in full is deliberate:
  all eight sectors have a field called `space`, so a bare `space` in a criterion is ambiguous in a state
  the model reads literally.
